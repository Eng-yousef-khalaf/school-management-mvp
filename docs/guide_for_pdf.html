1. 🏗️ معمارية النظام ومكدس التقنيات (Architecture & Tech Stack)

يعتمد النظام معمارية فصل الواجهة الأمامية عن الخلفية (Decoupled Client-Server Architecture)، حيث يعمل كل جزء بشكل مستقل ويتواصلان عبر استدعاءات برمجية مشفرة وآمنة بنظام RESTful APIs وجلسات توثيق JSON Web Tokens (JWT):

🖥️ الواجهة الأمامية (Frontend Web App)
React 19 + Vite 7 + Vanilla CSS Tokens + React Context API
Port: 5173 / Vercel HTTPS
▼ استدعاءات سريعة ومحمية (HTTPS / REST API / Bearer Token) ▼
⚙️ خادم العمليات والخدمات (Backend API Server)
Node.js 20+ + Express.js 5 + Zod Validation + Helmet + Rate Limit
Port: 4000 / Cloud Server
▼ استعلامات علائقية مشفرة ومفهرسة (Prisma Client Queries) ▼
🗄️ قاعدة البيانات المؤسسية (Relational Database)
PostgreSQL 16 (مع فهارس مركبة على المعرفات وتاريخ الحضور والدرجات)
Port: 5432 / Supabase / Local Docker
⚡ ميزة محرك البيانات الهجين (Hybrid Data Engine): الواجهة الأمامية مزودة بنظام ذكي في api.js يتصل بالسيرفر الحي إن كان متاحاً، وفي حال كان الخادم في وضع السكون السحابي، ينتقل النظام تلقائياً (0ms) للعمل على محرك محاكاة داخلي عالي الغنى mockData.js مع حفظ التعديلات بذاكرة المتصفح لضمان عدم توقف العروض أو تجميد الشاشات مطلقاً.

2. 🗂️ فهرس وهيكلية المجلدات الرئيسية للمشروع

المسار / المجلد النوع المسؤولية ومحتويات المجلد
/backend مجلد الباك إند خادم Node/Express، نماذج Prisma لقاعدة البيانات، الـ Controllers، والـ Services.
/frontend مجلد الفرونت إند تطبيق React 19، الصفحات والشاشات، المكونات، السياقات المركزية، وملف التصميم.
/docs التوثيق الفني أدلة الاستخدام المعتمدة، دليل النشر للنسخة المستقلة، ومواصفات النظام باللغة العربية.
/docker-compose.yml حاوية تشغيل تشغيل قاعدة بيانات PostgreSQL 16 محلية بضغطة زر دون الحاجة لتثبيت برامج إضافية.
/vercel.json ملف الاستضافة قواعد إعادة توجيه الروابط وتوجيه المتصفح على منصة Vercel السحابية.

3. ⚙️ تشريح ملفات الواجهة الخلفية (Backend) بالتحديد

تم تنظيم خادم الباك إند وفق نمط المعمارية الطبقية (Layered Architecture)، حيث تنفصل معالجة الروابط عن منطق العمليات وعن استعلامات قاعدة البيانات لضمان سهولة التعديل والصيانة:

أ. ملفات قاعدة البيانات (backend/prisma/)

  • schema.prisma (الأهم): الملف المسؤول عن تعريف جميع جداول النظام الـ 13، الحقول، المفاتيح الأساسية والأجنبية، القيود، والفهارس (Indexes).
  • seed.js: سكربت تشغيل أولي يغذي قاعدة البيانات بحسابات افتراضية واقعية (مدير، موظف شؤون، معلمين، طلاب، شعب، وسجلات حضور ودرجات).
  • reset_clean_slate.js: سكربت لتصفير وتنظيف قاعدة البيانات 100% وحذف كل البيانات التجريبية مع إبقاء حساب المدير الافتراضي، ويُستخدم فوراً عند بيع أو تسليم النظام لمدرسة فعلية.

ب. خادم التشغيل المركزي (backend/src/server.js)

نقطة الانطلاق (Entrypoint) لخادم Express 5:

  • تطبيق طبقات الحماية الأمنية (helmet للترويسات، و cors للنطاقات المسموحة).
  • تفعيل حماية تسجيل الدخول من محاولات التخمين (Rate Limiting).
  • ربط المسارات (Routes) وتجميعها تحت بادئة /api.
  • توفير مسار فحص الجاهزية /api/health وصفحة هبوط إرشادية للمطورين.

ج. طبقة المسارات (backend/src/routes/)

ملف المسار (Route) المسؤولية ونوع العمليات المعالجة
authRoutes.js تسجيل الدخول، التحقق من الجلسة، وتعديل كلمة المرور.
studentRoutes.js إدارة الطلاب، البحث والفلترة، واستيراد وتصدير ملفات Excel.
teacherRoutes.js دليل المعلمين، الجداول، دوام المعلمين، وتدوير الطاقم سنوياً.
classRoutes.js & subjectRoutes.js إنشاء وتعديل الصفوف والشعب والمواد والمناهج الدراسية.
academicYearRoutes.js إدارة السنوات الدراسية وتفعيل العام النشط وأرشفة القديم.
enrollmentRoutes.js تسكين الطلاب وتوزيعهم على الشعب في السنة الأكاديمية النشطة.
attendanceRoutes.js رصد الحضور والغياب اليومي والتسجيل الجماعي (Mark All Present).

developerRoutes.js مركز تشخيص المطور، قياس استهلاك التخزين، وتصدير نسخة احتياطية JSON.

د. طبقة الخدمات والمنطق التجاري (backend/src/services/)

هنا يكمن العقل الحقيقي للنظام وجميع استعلامات قاعدة البيانات الحسابية:

  • studentService.js: الفلترة متعددة المعايير، الترقيم (Pagination)، وإعداد الملف الشامل للطالب (360° Profile).
  • feeService.js: احتساب الرسوم المتبقية والخصومات، وتوليد أرقام إيصالات الدفع الرسمية (REC-YYYYMMDD-XXXX).
  • excelService.js: فحص ومعالجة ملفات Excel المرفوعة واكتشاف تكرار أرقام الهوية قبل إدخالها في قاعدة البيانات.
  • teacherService.js: حساب نصاب الحصص، وأداة تدوير المعلمين للعام الجديد بضغطة زر واحدة.
  • reportService.js: استخراج تحليلات اليونيسيف (UNICEF)، نسب النجاح والرسوب، ومصفوفة الدرجات.

هـ. طبقة الحماية والأدوات (backend/src/middleware/ & utils/)

  • authMiddleware.js: فك تشفير توكن JWT والتحقق من هوية وصلاحية جلسة المستخدم.
  • rbacMiddleware.js: التحقق من الصلاحيات بناءً على الدور (ADMIN, STAFF, TEACHER).
  • validateMiddleware.js & validators.js: تدقيق المدخلات بمكتبة Zod الصارمة.
  • auditLogger.js: تسجيل أي حركة حساسة (حذف، تعديل، ترقية) في جدول الرقابة تلقائياً.
  • prisma.js: كائن الاتصال الموحد بقاعدة البيانات لمنع استهلاك الذاكرة.

4. 🎨 تشريح ملفات الواجهة الأمامية (Frontend) بالتحديد

أ. قلب التوجيه والتحكم (frontend/src/App.jsx)

يدير التطبيق كـ (Single Page Application)، حيث يقوم بما يلي:

  • التعرف على الصفحة المطلوبة والتبديل بين الصفحات بدون إعادة تحميل المتصفح.
  • حراسة المسارات (Route Guards) والتأكد من امتلاك المستخدم للصلاحية المطلوبة.
  • التعرف التلقائي على البوابات المنفصلة: بوابة المطورين (/developer-hub) وبوابة أولياء الأمور للدفع السريع (/pay).

ب. سياقات إدارة الحالة المشتركة (frontend/src/context/)

السياق (Context) المسؤولية والبيانات المدارة

LanguageContext.jsx تبديل اللغة (العربية والإنجليزية)، عكس اتجاه الصفحة RTL/LTR، وقاموس ترجمة متكامل.
AcademicYearContext.jsx توفير السنة الدراسية النشطة حالياً لكافة الجداول والصفحات لمنع تداخل السنوات.
SchoolConfigContext.jsx إدارة هوية المدرسة، الشعار، الشعار اللفظي، وألوان النظام برمجياً ومن الإعدادات.
ToastContext.jsx نظام الإشعارات المنبثقة التفاعلية (نجاح، تحذير، خطأ).
NotificationContext.jsx إدارة جرس الإشعارات العلوي للتحويلات المالية الواردة والمتأخرات.

6. 💼 دليل الإجابات السريعة لنقاش الشركة البرمجية (Developer Cheat Sheet)

استخدم هذه الإجابات المحددة لتوجيه أي مهندس أو شركة برمجية مباشرة لمكان الكود:

❓ السؤال 1: "أين نذهب إذا أردنا إضافة حقل جديد في بيانات الطلاب أو المعلمين؟"
الإجابة المباشرة:
1. افتحوا ملف backend/prisma/schema.prisma وأضيفوا الحقل في نموذج Student أو Teacher ونفذوا أمر npx prisma migrate dev.
2. أضيفوا الحقل في قواعد التحقق بملف backend/src/utils/validators.js.
3. في الواجهة الأمامية، أضيفوا مدخل الحقل في نافذة frontend/src/pages/Students/AddEditStudentModal.jsx وفي جدول العرض StudentList.jsx.
❓ السؤال 2: "أين نعدل منطق احتساب الرسوم أو نضيف وسيلة دفع بنكية أو إلكترونية جديدة؟"
الإجابة المباشرة:
* في الباك إند: عدلوا في backend/src/services/feeService.js و backend/src/routes/feeRoutes.js حيث يتم حساب المبالغ وتوليد أرقام السندات.
* في الفرونت إند: افتحوا نافذة تسجيل الدفع frontend/src/pages/Fees/RecordPaymentModal.jsx وبوابة ولي الأمر ParentPaymentPortalStandalone.jsx لإضافة وسيلة الدفع وتعديل خيارات السند.
❓ السؤال 3: "أين نضيف تقريراً جديداً أو نعدل تصميم شهادات الطلاب وإفادات القيد؟"
الإجابة المباشرة:
* استعلامات التقرير وبياناته البرمجية تُكتب في backend/src/services/reportService.js.
* واجهة الشهادات والطباعة الرسمية موجودة في frontend/src/pages/Reports/BulkCertificatesModal.jsx وتقرير الطوارئ في UnicefAnalyticalReportModal.jsx.
❓ السؤال 4: "كيف نغير اسم المدرسة أو الشعار أو الألوان الافتراضية؟"
الإجابة المباشرة:
لا تحتاجون لتعديل الكود المصدري إطلاقاً! يتم ذلك عبر:
1. ملف الإعدادات frontend/.env عبر المتغيرات VITE_SCHOOL_NAME_AR و VITE_PRIMARY_COLOR و VITE_SCHOOL_LOGO_URL.
2. أو برمجياً من داخل شاشة إعدادات النظام frontend/src/pages/Settings/SettingsPage.jsx المحفوظة عبر SchoolConfigContext.jsx.
❓ السؤال 5: "أين نتحكم بالصلاحيات والأمان وما يراه كل مستخدم؟"
الإجابة المباشرة:
* في الباك إند: عبر وسيط الصلاحيات في backend/src/middleware/rbacMiddleware.js بحظر أو السماح للمسارات حسب دور المستخدم (ADMIN, STAFF, TEACHER).
* في الفرونت إند: يتم حجب أو إظهار الروابط في القائمة الجانبية Sidebar.jsx وفحص الصلاحية في App.jsx بالاعتماد على AuthContext.jsx.
❓ السؤال 6: "أين توجد أدوات المطورين والتشخيص والنسخ الاحتياطي؟"
الإجابة المباشرة:
افتحوا الرابط http://localhost:5173/developer-hub أو المسار ?portal=dev، والذي يفتح شاشة DeveloperFleetDashboard.jsx المربوطة بمسارات backend/src/routes/developerRoutes.js وتوفر لوحة حية لقياسات السيرفر وسعة التخزين والنسخ الاحتياطي بصيغة JSON.
